**Можно ли обрезать эмбеддинги без MRL?**

Обычно в поиске работает простое правило: чем больше эмбеддер, тем лучше ищет. Но вместе с моделью растёт и размерность вектора, а с ней индекс: миллион документов в float32 при 1536 измерениях — это ~6 ГБ, при 256 — ~1 ГБ.

Самый простой способ ужать индекс — обрезка: берём первые N компонент вектора, заново нормируем, готово. Есть даже метод, который специально учит модель хорошо переносить обрезку, — Matryoshka Representation Learning (MRL): https://arxiv.org/abs/2205.13147. Так учили, например, Qwen3-Embedding.

Но модель вполне может нормально переживать обрезку и без MRL. Проверил на RuBQ Retrieval из ruMTEB (57k документов, 1692 вопроса):
• FRIDA — 823M параметров, вектор 1536, __без MRL__
• Qwen3-Embedding-0.6B — 596M, вектор 1024, __учили с MRL__

nDCG@10 × 100, FRIDA / Qwen3:
```
1536: 72.5 / —
1024: 72.5 / 66.6
 256: 70.0 / 64.9
 128: 65.8 / 62.5
  64: 54.1 / 56.6
  32: 31.8 / 43.9
```

Что видно:
• FRIDA сжимается 1536 → 256 (индекс в 6 раз меньше) и теряет всего 2.5 пункта: 72.5 → 70.0
• FRIDA на 256 всё ещё лучше Qwen3 на полных 1024 (70.0 против 66.6) при вчетверо меньшем индексе
• MRL реально выручает только на совсем маленьких размерностях: на 64 и 32 Qwen3 впереди

**Мораль:** если в карточке модели нет MRL, это не повод не пробовать обрезку. Просто замерьте качество на своих данных на нескольких N. В SentenceTransformers это один аргумент:

```python
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("ai-forever/FRIDA", truncate_dim=256)
emb = model.encode(
    ["search_document: Цунами вызывают подводные землетрясения."],
    normalize_embeddings=True,  # заново нормируем после обрезки
)
print(emb.shape)  # (1, 256)
```
